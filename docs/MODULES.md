# 原版功能模块生成器

此文记录历史模块化生成器的实现与验收边界。生成器现归独立 `calculator/` 工程，最新操作台与安装方式见 [独立说明](../calculator/README.md)。主线无此依赖。默认蓝图已切换为 252×194×256、449,195 方块的模块化结构，完整 Minecraft GameTest 的 14 组场景已通过。

## 哪些是预设，哪些由代码生成

蓝图相关实现统一位于 Java 软件包 `top.lacrus.zephyrzeno.electroncalculator.BluePrint`。它包含逻辑编译、模块模板、布线、校验、蓝图读写、原版方块转换和生成命令；模组方块及汇编器保留在各自的软件包中。

- `VerticalFullAdder` 预设一个全加器的逐层电路搭法、缓冲接口和相邻位之间的进位连线。代码按位宽重复这些电路，形成多位加法器。
- `ModularLayout` 预设与门、或门、或非门及锁存器的搭法，并提供相互绝缘的输入、输出引脚。
- `DecimalCircuit` 描述十进制输入、运算、进制转换与显示逻辑；`PhysicalNetlist` 保留完整的多位加法器，不再把其内部拆成独立布线的或非门。
- 代码决定需要哪些模块、模块放在哪里，以及模块之间如何接线。模块内部的固定电路不会在每次生成时重新布线。
- `.ebp` 文件保存实际方块、朝向、接口和中文标牌的位置。它不保存操作数对应的结果查找表。

生成完成后，运算由 Minecraft 原版红石更新执行。Java 不监听输入拨杆、不计算答案，也不代替红石点亮显示屏。测试中的逻辑求值仅用于独立核对期望值。

## 已完成的验证

- 单位全加器：Minecraft 1.21.1 GameTest 验证全部 8 种输入，并验证回到零状态。
- 四位进位链：带原始测试接口时为 19×13×38，共 484 个方块，已验证实际进位。
- 四位加法器总线接口：带测试拉杆、灯的结构为 22×17×38，共 628 个方块；游戏内穷举 16×16×2=512 组输入。
- 十四位加法器：游戏内验证全位进位、最大值溢出、交替位输入和回到零状态，覆盖整机采用的最大位宽。
- 与、或、或非及原版中继器锁存模块：游戏内验证真值表、保持和解除保持。
- 模块组合：实际连接输入面板、与门、异或门、存储和灯段，验证计算和保持状态。
- 整机逻辑：原始逻辑和模块化逻辑分别验证 100×100×4=40,000 组运算；模块化结果逐项比较二进制值、BCD、状态标志和七段灯输出。

整机另外完成了全部 2,016 条模块网络的检查，以及世界内的 14 组场景验证。完整 GameTest 比较每个保留的物理模块输出与所有显示输出，覆盖加法、正负减法、最大乘积、四舍五入到两位小数、除零、锁存、解除锁存、非法数位和恢复零输入。2026-10-02 本机测试全部通过，整轮约 27 分钟；这不代表任意输入切换节奏或未加载区块下都能得到正确结果。

## 已修复的放置差异

原版红石粉的裸默认方块状态是点状。在代码放置孤立红石粉时，它不会像十字形红石粉一样给旁边的实心方块供电。生成器现在从十字形状态开始，再按实际邻居更新连接形态，与正常放置的行为相符。

模块接口保留独立接线空间。线路使用中继器恢复信号，并检查端点电平及中继器反馈回路；模块本体的真值由独立 GameTest 验证。

## 电路参考

- 竖直全加器使用两级同或逻辑，参考 [RubenHillier 的紧凑全加器](https://www.reddit.com/r/redstone/comments/1vld1df/)，在 Electron 中重新定义缓冲接口、进位连线和模块总线，并以 Minecraft 1.21.1 实测为准。
- 与门、异或门的基础布局参考 [Quan Nguyen 的标准单元库](https://github.com/qmn/pershing/blob/master/lib/quan.yaml)，按 BSD 条款使用；完整许可随 JAR 保存在 `META-INF/licenses/pershing.txt`。
